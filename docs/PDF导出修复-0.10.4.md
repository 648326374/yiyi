# PDF 导出修复 · 0.10.4

长篇文档可能全部生成译文，却因一个区域无法排版而无法导出。旧版遇到第一页问题就停止，重复导出不能解决这些问题，也无法一次看到后续页面的错误。

0.10.4 在导出前检查全书。界面「导出」默认生成可用结果：无法安全替换的区域保留原文，其余译文正常导出，任务中保存的译文不删除。成功后会显示保留原文的页数和区域数，同目录的 `<文件名>.pdf.issues.txt` 列出页码、段落 ID 和原因。仍可在待校对中修改后再次导出。文件损坏、磁盘写入失败等错误仍会中止，不能以保留原文掩盖。

本版同时修正以下问题：

- 目录点线按可用宽度重新排版，标题和页码分别定位，避免逐字复制点线导致换行溢出；目录项数量和页码必须与原文一致才启用此排版。
- 密集索引与图中标签可适度缩小字号，并在需要时收紧行距；不扩大到邻近段落或页面外，仍放不下时保留原文。
- 索引页码中的中文逗号按列表分隔处理，避免将 `179–181，229–233` 误读为带小数或千位分隔的数字。真正的页码变化仍会标出。
- 无窗口的 PDF 导出组件自动发现 Windows 字体，使数学上下标和扩展拉丁字符的回退字体可用于实际发行包。
- 全书检查与实际排版分别分批释放 PDF 解析缓存，保留取消与目标文件原子替换。
- 预览先创建单页工作副本，导出每批最多 32 页，避免 PDFium 每次改写页面时遍历整本带标签文档的引用关系。工作副本使用磁盘文件，最终只替换原页的内容与资源，保留目录、链接和页属性。
- 编辑前合并跨段的页面内容流，修复文字指令、图形路径跨流时出现的坐标偏移与裁切。合成用例先复现失败，修复后通过；实际书籍第 672 页已确认恢复。
- 原生页面含纹理填充资源（包括嵌套图形）时，当前导出组件无法可靠保留纹理，因此整页保持原文、原图，相关译文区域逐项列入清单。普通灰色与条纹在技术图示中可能代表不同含义，不能直接替换为近似填充。

用户提供的《Writing a C Compiler》共有 904 页，保存了 8,563 段译文。原任务只记录了第 13 页的导出问题；完整检查发现目录、密集索引等共 747 个未通过检查的区域。本版修复后，8,546 段使用译文，10 页中的 17 个区域保留原文并记录清单，其中第 664 页为整页纹理保护，包含 7 个译文区域。页码按 PDF 文件顺序，含封面与目录。完整导出约 187 秒，为本机单次结果。验证使用只读备份，未修改原 PDF 或用户原任务，也没有重新调用 AI 翻译。

最终测试、实际导出与发行包核验记录位于 `artifacts/0104/`，汇总见 [验证记录](验证记录.md)。第一轮验证发现导出复制分支误写空扫描页字段，独立正文检查和回归测试共同捕捉了该问题；中间文件单独保存在 `compiler-export/attempt-001-source-only.pdf`，不作为交付结果。

升级时先从托盘退出旧版，再启动新版，打开原书即可直接导出，无需清空译文或重新翻译。
