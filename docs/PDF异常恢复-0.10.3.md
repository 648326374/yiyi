# PDF 异常恢复 · 0.10.3

长篇 PDF 翻译中，服务偶发返回无关文字或异常标记时，旧版会保留已有译文，但立即暂停整篇任务，需要用户手动继续。0.10.3 保留内容校验，增加限次重试、失败段落记录和后续页面继续处理。

## 处理方式

- 自动任务中，内容校验失败后等待 1 秒、2 秒，最多再尝试 2 次。保持原模型、思考等级和原文；重试提示不会带入被拒绝的回答。
- 普通翻译中，同一段重试后仍失败，会保留该段原文并记入待校对，继续后续段落。连续 3 个段落均在重试后失败则暂停。
- 完成本轮遍历后仍有失败段落，会明确显示剩余段数，保留可继续任务。重新打开文件后，点击「继续」只补未完成段落。
- 「待校对」可定位到段落；「查看失败返回」只读显示最近一次被拒绝的内容，支持复制。异常内容不会被当作译文写入页面。
- 当前页重译仍然整页成功才替换。重试耗尽或用户暂停时保留整页旧译文，已通过校验的新段落暂存，继续后完成整体替换。
- 网络、HTTP、单页容量保护等其他错误仍会暂停。单段手动重译由用户明确发起，本轮未扩大为所有请求的自动重试。

## 本次故障验证

用户提供的《Writing a C Compiler》共 904 页。诊断时任务备份包含 1,404 个完整译文块，147 页翻译完成，游标停在物理第 158 页。当前浏览页码不等于任务正在翻译的页码。

在隔离的 SQLite 副本中，使用原有 OpenAI 配置、Responses 协议和 `gpt-6-luna / medium`，仅补译第 158 页。该页原有 5 段译文，剩余 10 段在约 33 秒内全部通过内容校验，本次没有触发异常重试。原有 1,404 个译文块逐项比对保持不变；原 PDF 的 SHA-256 未改变。未覆盖用户现有任务，也没有继续运行其余页面。

证据位于 `artifacts/0103/compiler-diagnosis/` 与 `artifacts/0103/compiler-replay-158/`。这些内容与个人配置不随发行包分发。旧版未保存截图对应的两次失败响应，本次成功重放无法还原其具体成因，也不足以评价模型的整体翻译质量。内容校验通过不等于语义、术语和分段衔接已经人工审校。

自动化回归覆盖两种 OpenAI 协议、两类异常返回、模型与思考等级保持、暂停取消延迟回调、重开续接、连续失败上限及整页重译的原子替换。最终执行记录见 [验证记录](验证记录.md)。

## 升级

从托盘退出旧版后启动 0.10.3，重新打开原 PDF，点击「继续」。已有译文和任务可保留，无需清空全书进度。
