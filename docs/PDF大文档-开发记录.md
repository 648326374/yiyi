# PDF 大文档处理开发记录

目标：取消整份 PDF 的固定文件大小、页数、总字符数和总段落数门槛，同时改进分页处理、进度存储、取消和导出。用户已授权按该方案逐步实现。此记录用于追踪完整范围，不以仅删除入口判断作为完成。

## 实施阶段

1. 文件与存储基础：只读内存映射、流式校验；独立 SQLite PDF 任务数据库、按页读写和有限页面缓存。保留单页异常对象、渲染尺寸等资源保护。
2. 分页任务流程：先读取文档信息，分批解析；优先当前页；工作组件只接收当前页或任务数据库引用。翻译和扫描请求继续逐块执行。统计增量维护，翻译非当前页时不重复生成当前页预览。
3. 缓存迁移：兼容旧版 JSON 任务，按原文和版式指纹恢复校对、翻译、结构与背景选择；分页保存已完成内容。重新打开、停止、失败时不丢失已保存结果。
4. 长任务控制：解析和导出显示页级进度并支持取消；按实际处理进展刷新超时。处理内存、临时磁盘和写入失败，避免写坏既有目标 PDF。
5. 长文档导出与交付：控制扫描背景和译文排版的峰值内存；核验原版式、图片、字体、可搜索文字、页数/尺寸和源文件完整性。更新说明、构建并核验便携包。

## 验收证据要求

- 超过原 50 MiB、300 页、100 万字符、5,000 段的文档能进入完整流程；任务累计数据超过原 32 MiB 后仍可保存和恢复。
- 超过 500 页、1,000～2,000 页及数百 MB 的文字、扫描、混合样例用于验证，不成为新硬上限。压测使用合成材料和模拟译文，不调用个人 AI 服务。
- 记录打开首个可用页面、翻页、后台解析、取消恢复、导出及进程内存。检查任务处理量增长时没有整篇缓存重复写入或无限积累页面图像。
- 旧任务迁移保留原文/译文修改、结构校正、跨页表头、扫描背景选择及确认状态；不覆盖或删除旧缓存。
- 原有 PDF / UI 功能回归通过；新测试覆盖分页、超过旧限制、迁移、异常恢复、原文件变动和导出取消。
- 检查实际发行包在独立中文路径启动、导出中文可搜索 PDF，并保留测试日志。
