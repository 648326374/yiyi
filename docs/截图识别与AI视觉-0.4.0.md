# 0.4.0 截图识别与 AI 视觉翻译

日期：2026-11-05。截图入口不变，弹窗内提供两种模式；同一张图可切换模式或重新识别，无需再次截图。TXT 文档翻译保留原有流程。

使用说明已随 0.4.2 更新：Windows OCR 及其实现已删除，本地识别只使用 RapidOCR；AI 改为先取原文，校对、复制后按需翻译。下方两种引擎及直接图片翻译的对照数据保留为 0.4.0 的历史实测记录。

## 使用方式

**本地 OCR**为启动后的默认模式。框选后自动运行 RapidOCR，在本机识别中英文，校对后可「复制原文」「放入原文」或「翻译文字」。同一张图可点击「重新识别」再次处理，无需选择引擎或识别语言。

**AI 识图取字**直接将当前截图交给所选视觉模型，一次请求返回原文，不先调用 OCR，也不自动翻译。切换模式或选择服务不会提交图片，必须点击「开始识别」或「重新识别」。服务可独立于工作台选择，选择保存在本机。原文逐步显示，完成后可编辑，使用与本地 OCR 相同的三个按钮。

同图切换分别保留两种方式的原文及修改；重新识别成功才替换该方式的结果。失败、取消或输出截断时丢弃本次未完成内容，恢复旧原文。复制使用当前编辑内容，不调用模型。点击「翻译文字」将编辑后的纯文本放入工作台并使用工作台当前模型翻译，目标语言与工作台共用；识图和翻译可以选择不同本地模型，翻译请求不携带图片。

服务编辑窗口新增「测试识图」，发送一张带随机字符的合成图片；正确读出才报告通过。预期字符不放进文字提示词，普通“OK”回答不能通过测试。测试失败可能是模型不支持视觉、投影模型缺失或字符读错；通过也不代表复杂截图识别一定准确。

截图及两份原文保留在当前弹窗中，关闭弹窗或重新截图时清除；识别不自动写入历史、文件或剪贴板。用户点击翻译后，成功结果按工作台的普通查询保存。OCR 的临时 PNG 在完成、取消或超时后删除。AI 图片以 PNG/Base64 直接附在请求内，仅发往选择的地址，没有公共图片上传服务。

## llama.cpp 配置

本次实测配置：

- 协议：OpenAI Chat Completions。
- 地址：`http://127.0.0.1:8080/v1`。
- 模型：服务 `/v1/models` 实际返回的 `.\Qwen3.5-2B-Q4_K_M.gguf`。
- 服务端加载对应 `Qwen3.5-2B-mmproj-F16.gguf`，保留用户的 `-rea off`、线程与采样设置。
- 客户端思考等级保持「跟随服务」，无自动参数调整或重试。

图片请求支持 Chat Completions、Responses、Ollama 原生、Anthropic 和 Gemini。接口格式正确不代表该服务或模型具备视觉能力；例如 llama.cpp 应选择 Chat Completions，而不是 Ollama 原生。

AI 请求限制为每边不超过 4096 像素、总像素不超过 1200 万、编码 PNG 不超过 8 MiB。超出时提示缩小截图，不会悄悄压缩小字。视觉、查词、文档翻译和连接测试互斥提交，避免挤占单槽本地服务。使用云端视觉服务时会发送截图并可能产生该服务的用量费用。

## 本地 OCR 实现

C++ / Qt 桌面程序启动独立的 `yiyi_ocr_worker.exe`。工作进程加载 `ocr/YiyiOcr.dll`，使用 RapidOcrOnnx 1.2.2 的检测和识别流程、ONNX Runtime 1.23.2 CPU、PP-OCRv5 mobile 检测/识别模型及匹配字表；分类器使用 `ch_ppocr_mobile_v2.0_cls`。无需 Python、CUDA 或 Windows OCR 语言包。

预处理保留原图，另生成 OCR 输入：透明背景铺白；边缘大面积为深色时反色；小图最多放大 2 倍，保留抗锯齿。检测最长边限制 2048，补边后处理，按检测位置整理从上到下、从左到右的文字。每个推理会话最多 4 个内部线程，关闭线程忙等。平均字符置信度低于 0.85 时提醒校对；该值不是准确率保证。

每次识别启动新的工作进程，完成即释放模型内存；超时 60 秒或取消时结束工作进程。启动和模型加载计入下方耗时。DLL 异常隔离于主程序，失败仅提示用户选择重试或视觉模式，不自动改换服务。

## 实测对照

本机合成截图，使用系统 Segoe UI / 微软雅黑字体；原始图像 650 × 130。每例每种引擎各执行两次，表中列第一次，重复结果一致。错误按忽略空白后的字符编辑距离计算，保留大小写及标点。此测试覆盖小字、深色和混合文字，不代表真实文档或任意截图的准确率。

| 样本 | 字号 | Windows 错字数 | RapidOCR 错字数 | Windows 耗时 | RapidOCR 耗时 |
| --- | --- | ---: | ---: | ---: | ---: |
| 英文两行 | 13 px | 0 / 55 | 0 / 55 | 377 ms | 413 ms |
| 中文两行 | 14 px | 3 / 25 | 1 / 25 | 313 ms | 330 ms |
| 深色中英混合 | 13 px | 12 / 34 | 1 / 34 | 317 ms | 328 ms |
| 深色极小英文 | 11 px | 1 / 66 | 0 / 66 | 295 ms | 335 ms |
| 深色中文 | 18 px | 0 / 21 | 0 / 21 | 299 ms | 327 ms |
| 三行顺序 | 22 px | 0 / 28 | 0 / 28 | 294 ms | 308 ms |

这 229 个参考字符中，Windows 16 处编辑错误，RapidOCR 2 处；仍有标点漏识别和 `AI` / `Al` 混淆。低清晰度、密集表格、多栏、竖排与手写内容仍需人工校对。

实际 Qwen3.5-2B 服务通过随机图片字符测试，用时 2210 ms；`Please close the door.` 截图直接返回「请关门。」，用时 1425 ms。只有这两次合成图片验证，不能据此保证长截图或复杂图片的耗时和准确度。未调用付费服务或更改用户服务端配置。

原始记录：`artifacts/040-ocr-benchmark/results.json`、同目录合成图片及 `artifacts/040-vision-check.log`。检查工具为 `yiyi_vision_check`，不进入普通自动测试或发行包；从 0.4.1 起 OCR 检查只运行 RapidOCR。

## 构建与打包

主程序继续使用 Qt / MinGW。OCR 桥接 DLL 单独用 MSVC x64 编译，通过 C ABI 调用；开发时需安装 Visual Studio C++ 工作负载。发行包已包含这些运行组件，使用者不需要开发环境。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-ocr.ps1
cmake --preset windows-mingw
cmake --build --preset windows-mingw -j 4
ctest --preset windows-mingw
powershell -ExecutionPolicy Bypass -File scripts/package.ps1
```

`setup-ocr.ps1` 默认使用 Visual Studio 18 2026，可用 `-Generator` 选择已安装的版本。脚本从 NuGet 下载微软发布的 `Microsoft.ML.OnnxRuntime` 1.23.2 包，提取编译所需头文件、Windows x64 原生库和许可证。依赖下载到 `artifacts/ocr-deps`，逐项验证固定 SHA256，再输出 `build/ocr`；自定义构建目录可用 `-OutputDirectory 构建目录/ocr`。运行期间不联网下载 OCR 组件。`scripts/build.ps1 -Package` 包含此准备步骤。

包中必须保留 `yiyi_ocr_worker.exe`、`ocr` 目录、Qt 动态库及插件；单独复制主 EXE 不能运行全部功能。第三方模型、代码、运行库来源和许可证见 `THIRD_PARTY_NOTICES.md` 及 `ocr/licenses`。
