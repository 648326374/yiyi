# PDF 模型等待与超时修复 · 0.10.1

日期：2026-11-07。

原客户端对所有 AI 请求使用固定 90 秒无数据超时。模型排队或推理超过这个时间且没有发送心跳时，客户端会主动中断。OpenAI Chat Completions 与 Responses 已正确发送所选思考等级，也没有额外设置 4096 token 输出上限；本次保留用户选择的模型与思考设置。

## 行为调整

- 普通 AI 生成请求默认允许连续 10 分钟没有服务数据；收到数据后重新计时。连接测试与测试识图仍为 90 秒。
- PDF「翻译设置 → 无响应等待」可选 5、10、20、30、60 分钟，设置保存在本机。运行中先暂停，再调整并继续；不需清空译文或重建任务。
- PDF 状态显示等待模型响应、服务已响应但仍等待正文、正在接收正文，以及当前请求用时。用时不是超时倒计时，也不是整份文档的耗时。
- 收到明确的协议完成标记后立即收尾，不再等待网关关闭 HTTP 连接。截断、拒绝和协议错误仍按失败处理。
- HTTP 408、504、524 明确提示为服务端或网关超时。客户端设置不能延长服务端自身的等待限制。
- 不自动重试，不调整模型或思考等级。暂停、失败时保留完整进度；当前页重译仍在整页成功后一次替换。

本地 PDF 解析、渲染与导出的 90 秒无处理进展保护保持独立。长时间仍无数据时可以主动暂停，避免一直等待；服务端是否停止处理由对应服务决定。

## 验证范围

测试使用临时配置、合成 PDF 和 localhost 模拟服务，不使用个人 API Key，也不调用真实 AI 服务。详细测试结果见 [验证记录](验证记录.md)。本次验证客户端等待、响应解析与任务恢复行为，不能据此判断实际服务的模型能力、排队时间或网关限制。
