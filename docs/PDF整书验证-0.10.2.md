## 已修复的问题

- **代码注释换行。** 技术书会把 `//` 注释排版到下一行，而不重复注释符号。结合缩进、自然语言和代码语法识别续行，支持数学记号、引号、破折号、省略号及行内注释。真实标识符、常量、字符串和语法仍受代码校验保护。
- **目录和引用下划线。** 忽略闭合路径产生的零长度边，正确计算变换后的线宽，并按文字行的实际基线识别短数字链接、缩放下划线及小型大写字母标题。下划线保留在原图中，不再使整个段落漏译。
- **完整段落。** 首行缩进不再把一句话拆成两个翻译请求；具有明显自然语言特征的两端对齐短行不再按每个单词切成一栏。代码字体中的说明文字与真正的程序代码分别处理。
- **公式旁文字。** 图片公式周围的文字拆成独立安全区域，避免因一个内嵌公式保护整个自然语言段落。文字仍受原图片边界约束。
- **上下标和字体。** 原生文字中的上下标与所属字符一起提取，避免翻译后留下孤立的指数。可用 Unicode 表达的上下标保留为对应字符，其余使用上、下标格式排版；独立的纯数学等式保留原始字形。中文字体缺少的数学符号使用 Windows 已安装字体回退，缺字仍明确报错。独立导出检查确认 `ϕ`、`⁻¹`、`˜` 等字符可正确提取，并核对了下标的字号和基线。
- **上下文和排版。** 短标题、词语参考文档开头与邻近原文，提示模型只给出当前片段的译文，不添加省略号或词典式备选释义。译文字号允许在原字号的 70% 与 8 点下限之间自适应；原字号小于 8 点时不放大。
- **重新解析与续译。** 解析版本升级后检查已走过的页码，补译新识别出的文字。段落编号变化时，用两侧均唯一且完全一致的原文复用译文；重复标签、不同原文和待更新译文不会被误认成已完成。
- **默认区域与手工调整。** 用原始布局摘要区分自动生成的区域和用户编辑。升级解析时采用新的默认区域，同时保留真正修改过的区域和原文。整书验证中的旧版区域另按相同原文、相同文字对象核对后刷新，并保留备份。
- **扫描表格边线。** 单元格背景清理限制在已识别的边界内部；背景采样仍使用完整文字框，避免把字形当成纹理。原图、底色框、自动清理和背景修复使用同一边界约束。函数名保持原样，说明文字照常翻译。
- **异常响应。** 新增异常 Unicode 字符、模型控制标记、异常括号序列，以及中英文目标下无来源文字脚本的检查；原文已有的其他语言文字和正常成对标签可保留。校验失败时保留旧译文与进度，提示重试，不把异常响应写成已完成段落。
- **纸张边界。** 真实导出发现原书部分长代码行位于页面右边界以外，导致正文区域也被扩宽，42 个译文块出现裁切。新提取的区域、容器和实际排版入口都限制在真实页面内；已有缓存同样受保护。回归覆盖四边越界、完全位于页面外的区域，以及长代码带来的错误宽度；检查实际导出的字形坐标，避免仅凭可搜索文字误判。

保留 0.10.1 的默认 10 分钟无数据等待和 PDF 等待时间设置。本轮也观察到服务端返回 HTTP 429，验证队列采用有限并发和退避等待；这与客户端超时不同。正常应用仍按原有任务流程发送请求，不因这些验证工具而开启后台并发。

## 验证工具与证据

`tools/check_pdf_book.cpp` 使用生产 `PdfController`，显式传入 `--run` 才会调用已配置的真实服务。分段任务独立保存 SQLite，重启复用已有译文，`--rescan-range` 可检查整个分段；分段结束后不导出误导性的“全书完成”文件。

`tools/check_pdf_book.py` 按各分段拥有的页码审计、合并和核对输出，检查源哈希、页码覆盖、模型、思考等级及待处理问题，不把各数据库中重复的基线译文相加。合并会拒绝未完成页、待校对问题和混合解析版本。独立核对使用 PyMuPDF 检查导出页数、尺寸、中文文本，以及原生图片的解码内容、位置和矢量路径；扫描或光栅化页面另行检查预览。

生产 PDF 工作进程新增内部 `checkLayout` 操作，复用预览的文字排版、数字和代码校验，并检查共享文字对象；它不代替图片背景处理和实际导出验证。

本轮回归结果、真实任务进度和导出验证记录分别位于 `artifacts/0102/` 与 `artifacts/directx12-book/`。书籍内容、任务数据库、配置和本地诊断文件均不随程序发行包分发。

最终校对另修正了服务返回的无来源词语、重复符号、残留英文连接词和部分术语，并将四处被拆开的标题合并翻译。最后两批共 70 条校对记录，前后页面保存在 `repairs/reviewed-tails-1794031007462357700/` 和 `repairs/final-terms-1794031650240715100/`。程序增加无来源重复符号检查；语义错误仍需人工校对，字符或关键词检查不能证明翻译完全准确。

原有书籍任务使用解析版本 13，并直接通过新版生产排版入口验证旧缓存；新任务的提取版本为 14。边界修复无需重新调用模型翻译已经完成的内容。
