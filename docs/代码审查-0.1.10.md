# 0.1.10 代码审查与修复

审查范围：AI 请求及流式解析、请求与界面状态、词条解析、配置与凭据存储、历史及收藏、QML 通用控件、构建和发行脚本。未继续此前暂停的 LFM3 兼容适配。

## 已确认并修复的问题

| 优先级 | 问题与影响 | 修复位置与处理 |
| --- | --- | --- |
| P2 | 除 Responses 外，只要响应包含 `error` 字段就被判为失败；合法的 `error: null` 回答也会显示空白“服务错误”。 | `src/aiclient.cpp`：区分缺失、null 和实际错误值；覆盖 Chat JSON / SSE、Ollama、Anthropic、Gemini。 |
| P2 | 长度检查发生在追加新数据之前，最后一段越界后如果连接结束，不会再次检查。超长回答可被接受，限制失效。 | `src/aiclient.cpp`：检查时计入本次新接收的数据，同时限制 Qt 读取缓冲；继续针对保留的正文和解析缓存检查，已消费的流式协议数据不挤占译文容量。 |
| P2 | Gemini 仅识别少量异常结束原因，`OTHER`、`BLOCKLIST`、`PROHIBITED_CONTENT`、`SPII`、`MALFORMED_FUNCTION_CALL` 等带部分正文的回答会被保存为完整结果。 | `src/aiclient.cpp`：明确结束时仅 `STOP` 视为正常，保留长度上限专用提示，其他异常结束不写入历史和收藏。 |
| P2 | 打包脚本在旧 `dist/Yiyi` 中增量部署，再压缩整个目录，旧 DLL、额外日志或其他手动放入的文件会一起发布。 | `scripts/package.ps1`：新建暂存目录部署；压缩完成后更新便携目录，旧目录及同版本旧压缩包备份到 `artifacts/package-backup-*`。版本从 CMake 读取，并核对 EXE，防止旧程序被打成新版本。 |

## 复现与回归

- 修改实现前，新加的响应测试出现 17 项失败：5 种 `error: null` 情况、JSON / SSE 两种超限边界、5 种 Gemini 异常结束各 2 种传输形式。日志：`artifacts/review-before.txt`。
- 修改实现后，专项测试 28 项通过，包含正常边界、流式协议开销、既有错误处理对照、初始化及清理。日志：`artifacts/review-after.txt`。
- 补充流式协议开销累计较大但有效正文很小时仍正常完成的回归，避免误伤长篇翻译，纳入完整核心套件。
- 最终完整 CTest 核心、界面 2 / 2 套件通过，耗时 109.22 秒；其中核心 122 项通过。日志：`artifacts/release-0110-ctest.txt`，详细结果额外保存为 `build/yiyi-core-results.xml`、`build/yiyi-ui-results.xml`。
- 中间有一次 CTest 核心套件返回失败，原有控制台日志没有记录具体用例。独立重跑核心 122 项通过，添加持久化 XML 日志后的完整 CTest 也通过，未能复现该次失败；具体原因尚未确认。独立重跑日志为 `artifacts/review-core-final.txt`。
- 打包版本检查已用旧 EXE 与新 CMake 版本不一致的情况验证：拒绝打包，现有便携程序的 SHA256 未变化。日志：`artifacts/review-package-version-guard.txt`。

自动化请求只访问本地模拟服务，使用临时配置与数据库，不读取个人 API Key，也不调用付费模型。源码保持原有提示词与用户选择的思考等级；本轮没有针对真实模型效果做新的评测。
